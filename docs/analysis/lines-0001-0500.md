## Control flow and data flow

- Initialization is eager. Namespace constants, generated UV tables, default SavedVariables, and helper closures are all created during file load.
- The atlas loops are deterministic pure table construction except for writes to file-local tables. `J` is a deep copy at the rectangle-table level, not an alias of `F`'s child tables.
- The game-over callback uses `timeToFade == -1` as a behavioral sentinel: reset/show/restore alpha versus hide. Both paths clear the `window.hiding` flag.
- `st` enforces at-most-one queue insertion while `animated` remains true.
- `ht` duplicates score into a display/controller object and engine state, then raises one-shot milestone transitions. Threshold flags prevent duplicate checks in a game. The function is incomplete at line 500, so score/level behavior cannot yet be considered fully mapped.
- `BejeweledData` and `BejeweledProfile` are overwritten with defaults before later initialization code is known. Preserving exact field names, scalar types, tuple order, encoded strings, and nil-vs-`1` booleans is mandatory until merge behavior is analyzed.
