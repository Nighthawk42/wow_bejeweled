## Control flow and data flow

- `LoadAchievementEvents` is now complete. Each conditional registration is keyed by a persisted `gainFunN` flag; callbacks return true after a successful skill gain so the watcher removes/unregisters them.
- Several achievements rely on old positional combat/event returns and live target state. Ready-check uses a secure hook rather than the watcher and therefore is not removed after success; it rechecks the persisted flag on every hook call.
- `VariablesLoaded` is one-shot orchestration: migrate/default data, construct options/achievement state, apply visibility/position, expose compatibility integrations, and nil bootstrap functions.
- The legal popup correctly inherits `BackdropTemplate`, but its background override targets `n.bgFile`, not the descriptor. The click handler also contains a visible debug print.
- High-score sync serializes leaderboard tuples into `*`-delimited chunks, with transport flushing only after the built string exceeds 180 characters. Incoming `Ee` trusts channel to choose friend/guild destination, then uses existing checksum validation in `j`.
- `ScrubLists` removes duplicates and departed contacts, but shifts only tuple fields 1–3. Authenticated field 4 remains attached to the old row, violating the row invariant proven in batch 02.
- Saved game state is a 9-row wire table: eight grid rows plus a metadata row. Special big-star state is encoded by adding 10 to gem contents; score field 9 is authenticated.
- `Q` is a destructive gem-frame reset. It removes all numeric-valued dynamic keys before restoring required geometry/visual defaults.
- `Ke` begins a board-wide animation transition, with special handling for hyper gems and random velocities; completion awaits batch 05.
