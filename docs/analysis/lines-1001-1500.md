## Control flow and data flow

- `M` is complete. It combines combo base score, match-length bonuses, special/power bonuses, mode multiplier, and level multiplier; reports the floored result through animation but does not itself apply the score in this body. Skill checks return numeric gains accumulated into one `+1 Skill` message per point.
- Match presentation position is derived from an anchor and orientation. Hyper-cube creation (`u`) awards its skill but intentionally suppresses the ordinary score popup.
- `ze` is a one-shot loader: choose faction, materialize a large four-region adjacency graph, detach its event, self-nil, then request garbage collection. Coordinate strings are opaque graph node IDs; numeric values are empirical travel durations, including zeros/fractions.
- `T` couples authoritative grid frames, animator objects, timer visibility, pause state, and mode-specific UI. Its dynamic `t[l](t)` call uses strings `Hide`/`Show`. Alpha bookkeeping and mode asymmetry must be preserved as evidence until intentionally fixed after full analysis.
- Flight observations consume queued triples and persist nested account-wide timing data. The “close estimate” path averages against stored data, while outliers over five seconds replace it.
- Achievement event dispatch stores arrays per event and removes a callback after it reports success. Registration is conditional on profile flags, minimizing callbacks for completed achievements.
- The batch begins legacy combat-log, battleground, loot, kill, and resurrection contracts. Multiple handlers rely on positional event varargs and implicit globals; these are migration hazards, not acceptable future patterns.
